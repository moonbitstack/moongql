The hall of one window

One endpoint, every type, no client-side joins.

A REST service spreads its data across dozens of little windows — one per resource, one per endpoint — and to gather three facts you must open three windows and walk between them. GraphQL keeps a single aperture. You point it at the part of the graph you want, and the response is cut precisely to that shape: no over-fetching, no second journey. The type system is the map; the query is the path; the response is the light that falls where you aimed.

Query — the beam you send Graph — every star and filament Response — the pool on the ground

moongql builds that graph in code: object types and fields become a schema, the schema prints to SDL and parses back to the same schema, and a query runs across every backend MoonBit targets.

What the schema gives you

A complete GraphQL surface, in pure MoonBit.

No runtime dependencies, verified on every backend (wasm, wasm-gc, js, native) in CI.

Graph

Code-first schema

Build object, input, enum, interface and union types in code. Print them to SDL and parse SDL straight back — print-then-parse yields the same schema, descriptions and all.

Query

Execution & validation

A hand-written lexer and recursive-descent parser turn a query into an AST; the executor walks it with a resolver map and a spec-compliant validator flags bad documents with line and column.

Response

Built-in IDE

A GET on the endpoint serves GraphiQL, Apollo Sandbox or Altair from a pinned CDN — or nothing, for production. One line chooses which.

Graph

Subscriptions

Stream payloads over graphql-transport-ws; the protocol state is plain data, so a server drives its timers and the whole pipeline runs anywhere.

Plaster

Apollo Federation

Compose subgraphs with @key, @shareable, @requires and the rest — v1 and v2 — and answer a federated query with the ordinary executor.

Query

#gql annotations

Write the schema and resolvers from your own types. The generator emits register(schema, resolvers) and the ToGql/FromGql bridges.

The endpoint, in a browser IDE

Three IDEs behind one endpoint.

Each is a single HTML page whose assets are pinned to an exact version, so the page a client sees a year from now is the page you shipped. The subscription socket is derived from the page's own location unless you name one.

// one endpoint, your choice of IDE
let app = @moongql.graphql_app(schema, resolvers)                    // GraphiQL
let app = @moongql.graphql_app(schema, resolvers, ide=@moongql.apollo_sandbox)
let app = @moongql.graphql_app(schema, resolvers, ide=@moongql.off)  // no IDE: GET without ?query= is 405
Print, parse, print again

The schema you write is the schema you get back.

Schema::of_sdl parses a schema document into a Schema; to_sdl prints it out. Round-trip the two and the second print is byte-for-byte the first — descriptions, @deprecated(reason:), argument defaults, directives, implements and the schema { … } block all survive the trip.

let s = @moongql.Schema::of_sdl(
  #|type Query {
  #|  "The user with this id."
  #|  user(id: ID!): User
  #|}
  #|type User {
  #|  id: ID!
  #|  "Use `name` instead."
  #|  legacyName: String! @deprecated(reason: "use name")
  #|}
  ,
)
s.to_sdl()  // the same SDL, normalised
