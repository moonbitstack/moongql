GraphQL over HTTP

One request, six answers.

The same endpoint, driven by the transport rules: what a POST carries, what the Accept header chooses, and what a client gets back when the request is wrong. Pick a case.

A POST with an application/json body, asking for application/json back.

content-type: application/json
accept: application/json

{ "query": "{ user(id: \"1\") { id name } }" }

200 · application/json

{"data":{"user":{"id":"1","name":"lfanke"}}}

The same query with the id in a variable instead of the document.

{ "query": "query ($uid: ID!) { user(id: $uid) { name } }",
  "variables": { "uid": "1" } }

200 · application/json

{"data":{"user":{"name":"lfanke"}}}

A body the endpoint cannot read as JSON: a request error, not a field error, so it is refused before any document runs.

415 · unsupported media type

{"errors":[{"message":"..."}]}

415 is the status the transport assigns to a missing or unsupported content-type, so a client can tell it apart from a GraphQL error.

With accept: application/graphql-response+json the status separates the two kinds of failure: 400 when the request never ran, 200 when a field failed while the rest of the response succeeded.

400 · the document did not run

{"errors":[{"message":"Cannot query field 'nope' on type 'User'",
           "locations":[{"line":3,"column":5}]}]}

An array body is a batch: each entry is executed on its own and the answers come back in the same order.

200 · application/json

[{"data":{"user":{"name":"lfanke"}}},{"data":{"hero":{"id":"1"}}}]

A GET carries the same fields in the query string. It runs only queries — a mutation over GET is refused.

GET /graphql?query={ user(id: "1") { name } }

200 · application/json

{"data":{"user":{"name":"lfanke"}}}

Serve the endpoint with no IDE and a GET without ?query= answers 405 instead of a page.

Print, then parse

The schema the code builds, as text.

to_sdl writes the type system out; Schema::of_sdl reads it back. Descriptions, argument defaults, @deprecated(reason:) and custom directives all survive the trip, so the second print is byte-for-byte the first.

schema {
  query: Query
  mutation: Mutation
}

directive @tag(name: String!) repeatable on OBJECT | FIELD_DEFINITION

"The root of the graph."
type Query {
  "Whoever is asking."
  me: User
  "Search the graph."
  search(filter: UserFilter, first: Int = 10): [SearchResult!]!
  "The old way."
  legacy: String @deprecated(reason: "use search") @tag(name: "gone")
}
